# 14. AI 연결 (Claude · Gemini · ChatGPT)

> 상태: ✅ 연결 기반 (회사-모델 쌍별 키, 연결 테스트, 기본 모델, 공통 호출 함수) / 🔲 NPC 자동 대화 (시나리오 연동)

향후 NPC가 AI로 자유롭게 대화하도록 하기 위한 기반이다. 지금은 **연결 설정과 테스트**까지 되어 있고, 실제 NPC 대화는 아직 연결하지 않았다.

## 메뉴 ✅ (2026-11-28 4차 개편)
- 타이틀 `AI 연결` 버튼, 또는 게임 중 설정 → 계정·AI 의 `AI : 회사 - 모델` 옆 `AI 연결` 버튼.
- **여러 개를 연결해 둘 수 있지만 게임에서는 기본 모델 하나만** 쓴다.
- **키는 회사-모델 한 쌍마다 하나** (예: `Anthropic - claude-opus-5-5` 와 `Anthropic - claude-haiku-5-5` 는 키를 따로 가진다).

| 위치 | 내용 |
|---|---|
| 맨 위 상자 | `AI 회사`(드롭다운: Anthropic·Google·OpenAI) · `모델명`(드롭다운: 첫 줄 **직접 입력** + 회사별 최신 모델 목록, 직접 입력을 고르면 옆에 모델 ID 입력칸) · `API 키`(입력칸) |
| 상자 아래 버튼 | `연결하기` — 입력한 키로 그 모델에 한 번 호출(연결 테스트). **성공하면 연결 목록에 넣고 기본 모델로 지정**, 실패하면 오류만 보여 주고 저장하지 않는다. `삭제하기` — 그 회사-모델 연결을 끊고 키를 지우며 아래 목록에서도 뺀다(확인 창 없음). 키 발급 링크 |
| 아래 목록 | **연결된 모델만** `회사 - 모델` 한 줄씩. 기본 모델에 `기본` 표시. 줄을 누르면 위 상자가 그 설정(회사·모델·키)으로 바뀌고 기본 모델이 된다. 오른쪽 `삭제` 로 바로 삭제 |
| 맨 아래 | `NPC 자동 대화 사용` 체크 — 지금은 설정값만 저장한다 (🔲 NPC 연동 시 사용) |

- 회사·모델을 바꾸면 이미 연결된 쌍이면 그 키를 입력칸에 보여 준다.
- 기본 모델을 삭제하면 남은 연결 중 첫 번째가 기본이 된다 (없으면 `연결 안 됨`).
- 예전 형식(회사마다 키 하나)의 설정은 처음 불러올 때 `회사 - 그때 고른 모델` 연결로 옮긴다.

| 제공자 | 호출 방식 | 기본 모델 | 목록 |
|---|---|---|---|
| Claude (Anthropic) | **공식 SDK** `@anthropic-ai/sdk` 를 `esm.sh` CDN 에서 필요할 때 불러온다 (`dangerouslyAllowBrowser: true`) | `claude-opus-5-5` | `claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-5-5`, `claude-fable-5-2` |
| Gemini (Google) | REST `generativelanguage.googleapis.com/v1beta/models/{model}:generateContent` (`x-goog-api-key` 헤더) | `gemini-2.5-flash` | `gemini-2.5-flash`, `gemini-2.5-pro`, `gemini-2.5-flash-lite` |
| ChatGPT (OpenAI) | REST `api.openai.com/v1/chat/completions` (`Authorization: Bearer`) | `gpt-5-mini` | `gpt-5-mini`, `gpt-5`, `gpt-5-nano`, `gpt-4.1-mini` |

- 모델 목록은 입력 도우미일 뿐이다. 새 모델이 나오면 `직접 입력` 으로 이름을 적으면 된다.
- Claude 호출: NPC 대화는 짧은 답이 목적이라 `output_config.effort = "low"` (4개 모델 모두 지원). Opus 5.5·Sonnet 5.5·Fable 5.2 는 거절(refusal) 시 서버가 다른 모델로 다시 시도하도록 `fallbacks: "default"`(beta `server-side-fallback-2026-07-01`)를 켜고, Haiku 5.5 는 서버 측 fallback 이 없어 일반 호출한다. 응답의 `stop_reason` 이 `refusal` 이면 오류로 알린다.
- 이 모델들은 생각(thinking)이 항상 켜져 있어 출력 토큰을 함께 쓰므로, 연결 테스트·NPC 답변의 `maxTokens` 는 1024 로 둔다.
- 모델 목록은 2026-11 기준 공식 문서에서 확인된 ID 만 넣었다. 새 모델은 `직접 입력` 으로 쓴다.

## 키 보관 원칙 ✅
- 키는 **이 브라우저의 localStorage (`ai_settings`) 에만** 저장한다. 게임 서버·Firestore·GitHub 로 보내지 않는다.
- 저장 형식: `{ active: "claude|claude-opus-5-5", npcEnabled, conns: [{ pid, model, key }] }`
- 브라우저에서 직접 호출하므로 키가 그 PC 에 남는다. 공용 PC 에서는 저장하지 말라고 메뉴에 안내한다.
- 사용 요금은 각 회사 계정에 청구된다.
- 공개 배포에서 모든 플레이어가 하나의 키를 쓰게 하려면 키를 숨길 서버(예: Firebase Functions — Blaze 요금제 필요)가 있어야 한다. 지금 구조는 "각자 자기 키" 방식이다. 💡

## 코드 (`js/ai/ai-client.js`)
| 함수 | 설명 |
|---|---|
| `AI.chat({ system, messages, maxTokens, conn })` | 공통 호출. `messages` 는 `[{ role: "user"|"assistant", content }]`. `conn`(`{pid, model, key}`)을 안 주면 기본 모델. 응답 문자열을 돌려준다 |
| `AI.npcReply({ name, persona, history, playerText })` | NPC 용 편의 함수. "이 NPC 로서 한국어 1~2문장" 시스템 프롬프트를 붙여 기본 AI 로 호출 |
| `AI.ready()` · `AI.activeConn()` · `AI.label()` | 기본 모델이 있는지 · 기본 연결 · `회사 - 모델` 표시 문자열 |
| `AI.upsert(pid, model, key)` · `AI.remove(pid, model)` | 연결 추가(기본으로 지정)·삭제 |
| `openAIMenu()` | AI 연결 창 |

## NPC 자동 대화 계획 🔲
1. 시나리오에 AI NPC 표시 (예: `@event` 의 `* ai 성격 설명`) — 문법은 [11_scenario.md](11_scenario.md) 에 추가할 것.
2. 말을 걸면 기존 대사 후 "자유롭게 말하기" 선택지 → 게임 안 입력창 → `AI.npcReply` → 대화창에 출력.
3. 키가 없거나 `NPC 자동 대화 사용` 이 꺼져 있으면 기존 대사만 나온다.
4. 대화 기록은 맵을 떠나면 버린다 (세이브에 넣지 않음).
